# DevJay user guide

See the [README](../README.md) for installation and first steps. This reference covers everyday controls, Git actions, and recovery.

## Sites and Settings

Open Settings and drop a folder from Finder into the Sites list. Any folder is accepted; Git clones and worktrees get branch/status information. Symlink aliases of an existing Site are rejected. Site registration never creates, deletes, or checks out a repository. The **×** beside a Site asks for confirmation, then unregisters it and closes its windows, leaving its folder unchanged.

**Window decoration** offers **None** (default, content only), **Minimal** (borderless with small controls on both the panel and Sites), and **Normal** (native macOS title bars). The choice applies immediately to the panel and all Sites and is saved between runs. Settings uses a normal macOS title bar and fits its content height when opened, up to the available screen height. Escape and the native close button close it. Right-click anywhere on a card for a native context menu; its last two items are **DevJay settings…** and **Quit DevJay**. Command-comma also opens Settings. Shift-F10 or the Context Menu key opens the menu for a focused card control. Hover tracking also works while DevJay is inactive, without taking focus from another app. Click a panel card, above or below the divider, to activate its Site. Settings, other controls, and selecting status text retain their own behavior. With Settings closed, drag that heading to move the whole panel. Drag an independent Site by its heading; the PR tag and status area do not move it. Place each Site window on its desired monitor and desktop using Mission Control. Choose **By name** to sort by directory name (case-insensitive, with the full path breaking ties), or **Manual** to use the saved custom order. Drag a row by its dotted handle to reorder; this switches to Manual. Keyboard users can focus the handle and press Up or Down. The selected order also controls the main panel.

Cards show a subdued parent path, bold directory name, branch, local edits, upstream comparison, and GitHub review state when available. A colored **#1234** tag appears in the upper-right corner for each associated PR, using the branch font size. Cards without a PR omit both the tag and the old “No open PR” line. Hover a card for its full path, desktop, upstream, and last successful remote-check time. The strip can be resized and scrolls horizontally when needed. Cards show their full status content; Site windows and the control panel grow taller when necessary, preserving their width and bottom-edge placement. They keep the extra space when status becomes shorter. If the display cannot fit all content, scrolling is available in the outer window or card list.

**Control panel always visible** keeps the main window on ordinary desktops on its monitor; it does not duplicate it across monitors. **Show all windows on top** floats all DevJay windows. Both default to enabled, persist between runs, and remain available in the View menu. Settings is a separate window; closing it or pressing Escape leaves DevJay running.

The Sites menu provides Command-1 through Command-9 for the current card order, and Command-0 for DevJay. These are app shortcuts, not global hotkeys. Command-Q quits DevJay when the app is active and saves the layout; the control strip does not take keyboard focus, so keyboard shortcuts stay with the previous app until you activate a Site or open Settings. The strip supports mouse controls, dragging, and context menus; use Site windows or Settings for keyboard interaction. The panel’s × button is available in Minimal decoration, and the native close button is available in Normal decoration. With any decoration, right-click a card and choose **Quit DevJay** to quit without needing keyboard focus. Remove Sites in Settings; Site windows have no close controls. Selecting a minimized Site restores it.

For navigation, enable System Settings → Desktop & Dock → Mission Control → **When switching to an application, switch to a Space with open windows for the application** if needed. Keep the app's Dock assignment at **None** so windows can occupy different Spaces. No Accessibility permission or editor integration is required.

## Control panel layouts

Settings offers **Horizontal** (default), **Vertical**, and **Custom**. Custom initially wraps cards into tiles as the window is resized. Only while Settings is open, drag a card by its heading: Horizontal and Vertical reorder the cards; Custom saves free positions on an invisible 8-pixel grid and allows overlap. Moving a card brings it above overlapping cards. **Reset card positions** in Settings returns Custom to automatic tiling. Layout and custom positions survive restarts. Dragging while Settings is open switches sorting to Manual. Status text remains selectable for copying; drag the panel background to move the window while rearranging cards.

## Inspect changes

Card status texts highlight on hover, even in inactive windows. Click **In sync**, another Git status, or a card’s **edits**, **local commits**, or **remote commits** count to open a read-only changes window, from either the control panel or an independent Site. Local edits are grouped into staged, unstaged, and untracked files. Select a file to see its unified diff, with line numbers and colored additions and deletions. Available suggested actions appear inside the viewer and update with the current checkout. Up to three direct action buttons appear, with the recommended action on the right and secondary choices subdued. Clicking an action such as **Push 3 commits** starts safety checks and opens **Confirm push**; a separate confirmation is required to apply it. Opening a viewer never changes the checkout. Clicking another category reuses that Site’s existing changes window and selects the category. Right-click a count or status to choose between viewing that category in an existing window and a new independent window. If several windows exist, DevJay prefers one already on the requested category, then the most recently used. Each window keeps its own selected commit, file, and snapshot. The file summary and staged/unstaged/untracked section headings show file counts and total added/removed lines. The overall count includes each path once; line totals sum staged and unstaged changes separately. Binary changes are excluded from line counts, and unavailable or limited counts are labeled partial. The viewer does not stage, commit, or change files.

Select a file and click **Open in GoLand** (or your chosen editor) beside its diff. In **Settings → Editor**, choose one preferred editor for all Sites. Enable **Automatically use the editor with this project open** to prefer a detected project editor, falling back to your preferred editor when no unique match is available. Installed editors and **Choose another application…** are available there. Project detection recognizes a running JetBrains IDE reporting that exact checkout open, using its optional discovery metadata and verifying the live application. If detection is disabled, DevJay always uses the preferred editor. macOS asks the existing application to open the file; project-window routing is handled by that editor and is best effort. No Accessibility permission is needed. Opening always uses the current working-tree file, even while viewing an older commit. Deleted files and links outside the checkout cannot be opened from the viewer.

The local-commits view shows commits not yet in the upstream history. **Remote commits** shows the full upstream history, in pages of 100, with each commit labeled **Incoming** or **Already local** relative to the captured local branch. These labels compare commit IDs, so rebased equivalents can still be marked incoming. Select a commit, then a file, to inspect its changes. Merge commits are compared with their first parent. **Rebased · ready to publish** also opens the viewer; its tabs let you inspect both sides of rewritten history.

For a branch without an upstream, commit counts and history use the cached same-name branch on `origin`, or `origin`'s default branch when no same-name branch is available. The viewer names this comparison and labels it **No upstream configured; cached comparison**. For example, an unpublished branch with three commits beyond `origin/main` shows three local commits and the history of `origin/main`. This comparison does not configure tracking or enable a push; publishing a new branch remains manual. If neither comparison is available, counts remain unavailable rather than showing zero.

Changes windows reread local Git data every 10 seconds after the previous refresh finishes, and sooner when the Site’s Git status changes. This also catches edits whose file count stays the same. Automatic refresh keeps the current file or commit when possible, including following commits onto another history page. It preserves scroll position for the same diff and leaves unchanged diff text in place for copying. If the selection disappears, the first available entry is selected; a note explains when the previous commit could not be located. Branch changes reset the selection. **Refresh** remains available for an immediate reread. Each displayed comparison uses a consistent set of captured revisions until the next refresh. Remote fetches remain on the separate background monitoring schedule. Binary files show a notice, and large file lists and diffs have explicit display limits. Escape or the native close button closes the viewer.

## Open pull requests

Click a card’s PR tag (or its review status) to reuse an existing tab showing that PR. DevJay checks running **Safari, Google Chrome, Microsoft Edge, and Brave** windows only when you request a PR action. A tab showing the PR’s Files, Commits, or discussion page counts as the same PR. It selects that tab and activates its browser window; switching macOS desktops depends on the browser and Mission Control settings.

Right-click the tag for **Open PR #1234** and **Open PR #1234 in new tab**, followed by **DevJay settings…** and **Quit DevJay**. A new tab prefers an existing window that already contains GitHub PR tabs, then a window in the supported default browser. If no suitable window exists, DevJay opens the URL in the default browser, whose preferences determine tab versus window placement.

macOS may request **Automation** permission for each running supported browser. Access can be managed in **System Settings → Privacy & Security → Automation**. If inspection is denied or unsupported, DevJay falls back to ordinary URL opening; it cannot promise reuse in that case. Tab URLs are inspected only for this action, never stored or polled in the background; page contents are not read. No Accessibility permission or “JavaScript from Apple Events” setting is required.

## Git monitoring

Local status is polled every 3 seconds. Local commands have four reserved slots, separate from the two network-command slots. Failed local readings preserve the last complete status and PR findings with an explicit cached-status warning, without forgetting the upstream or retry schedule. Remote and GitHub checks run in the background about once a minute, independently of local polling, with at least a minute between completed attempts and retries. Status distinguishes no upstream, detached HEAD, an empty repository, local changes, merge conflicts, ahead, behind, diverged, and a removed upstream branch. Non-Git and unavailable folders remain usable Sites with an explanatory status.

Automatic monitoring fetches the configured upstream and the remote default branch into their remote-tracking refs, with tags, submodule recursion, maintenance, and configured extra ref mappings disabled. Monitoring never changes checked-out files or local branches. Offline/authentication failures retain cached comparisons and label them explicitly; they are never represented as a fresh “Up to date.” When a feature branch has moved onto a newer default-branch base and every remote-only commit has an equivalent local patch, the card shows **Rebased · ready to publish** instead of misleading incoming/outgoing counts. Commit counts remain in the tooltip. Unverified remote status is labeled explicitly; genuinely new remote patches or unverified merge commits retain normal divergence warnings. Publishing rebased history remains manual with force-with-lease; DevJay does not suggest pulling the old history. A non-fast-forward change to the observed remote-tracking ref is flagged as rewritten history. Rewrites that occurred before the first observation or were fetched by another tool between checks cannot always be identified.

Suggested actions appear in a Site’s changes window when its checkout is at the exact tip of a merged PR, has local commits ahead of origin, has incoming upstream commits, or is missing commits from the remote default branch. The compact cards have no action buttons; click a status to open the changes window. Return-to-default suggestions require an exact repository, branch-name, and merged-tip match with no staged, unstaged, or untracked edits. Reusing a previously merged branch name does not qualify. Click the specific action to fetch and check the exact source and destination commits, then explicitly confirm **Update branch**, **Return to the default branch**, **Rebase branch**, or **Push commits**. Confirmations expire after five minutes and cannot be reused. Cancel, ×, and Escape discard pending confirmation. Returning after a merge offers optional local branch deletion in the confirmation dialog; changing that option repeats the safety checks. Once an operation is applying, closing waits until it finishes. Quitting keeps the app responsive while waiting for the confirmed action. Network commands have individual timeouts; local checkout mutations are allowed to finish.

- Updates only fast-forward a clean checkout to its confirmed upstream commit. Ordinary divergence requires manual handling; verified rewritten upstream history may qualify for **Replace from remote**, described below.
- Returning after a merge switches to the repository’s default branch and fast-forwards it, creating it with remote tracking if absent. Both returning and optional deletion require the old branch tip to match a PR merged into that default branch. Deletion happens only after a successful switch and update; another worktree using the branch blocks it.
- Rebases are tested in a disposable repository against the latest fetched default branch, preserving merges. Conflicts show the files at the first stop and recommend a manual rebase. Confirmation repeats the trial and installs only its conflict-free result, using your Git committer identity. The original branch moves with an expected-old-commit check, and no rebase is left in progress in the Site. No repository hooks, custom merge drivers, filters, or saved conflict resolutions run in the trial. Repositories requiring signed commits must be rebased manually.
- DevJay retains recovery refs for the ten most recent verified successful checkout actions. Failed or partial actions keep their backups. Backups made by older versions are also retained because their outcome cannot be established safely. These refs are local, but Git mirror pushes can publish them; review refs before using `git push --mirror`.

A normal push is suggested for local-only commits with an existing same-name origin upstream. Review fetches origin and verifies that its tip is an ancestor of the local branch; confirmation pins the source commit and destination, rechecks both, and pushes only that branch without force or tags. Different/multiple push URLs require a manual push. Remote changes, divergence, or local edits found before pushing stop the action. Edits made while the push is in flight do not turn a verified remote success into a failure. The result is checked against the remote even after a command error or timeout, with no automatic retry. Rebased history still requires manual publishing.

Actions recheck checkout identity, HEAD, branch, remote, clean index/files, and Git operation state. They refuse staged/unstaged/untracked work, hidden index flags, sparse checkouts, and submodules. Git’s no-overwrite-ignore behavior protects incoming collisions with ignored files. Actions are serialized per common Git directory; they cannot provide atomic protection against arbitrary concurrent writes by other tools or unsaved editor buffers. No automatic stash/pop, destructive reset, clean, or push is performed. Errors report the observed checkout state rather than attempting a blind rollback. If an external change interrupts the rebase’s branch reattachment, the message explicitly explains the detached checkout and manual next step.

**Replace from remote** is offered for a clean branch whose exact local tip appears among the last 256 recorded tips of its same-named upstream, and is no longer an ancestor of that upstream. This handles force-pushed history, including rewritten merges and multiple remote rewrites. It does not infer safety from commit dates, messages, or similar patches. Missing or expired reflog evidence, local commits beyond the recorded tip, edits, untracked files, hidden index flags, or another worktree using the branch stop the action. Preparation fetches the upstream; confirmation rechecks the local state, evidence, and exact remote tip. A recovery reference retains the old commits before the branch is moved to the confirmed remote commit, preserving its name and tracking. No forced checkout, destructive reset, or remote push is used. If interrupted after detaching, the result explains how to finish manually. Changes made concurrently by other Git clients cannot be locked out entirely.

Before updating, replacing, rebasing, or switching a local branch, DevJay preserves the original commits at **refs/devjay/backups/<action-id>**. The result window displays that reference. List retained recovery points with `git for-each-ref refs/devjay/backups/`; create a separate recovery branch with `git branch recovered-work <recovery-ref>`. These references survive restart; retention follows the ten-successful-actions policy described above, while failed, partial, and legacy backups remain available. They preserve commits, not uncommitted or ignored files.


For GitHub.com remotes, `gh pr list` supplies open PR number, draft state, and review decision. DevJay also reads all pages of submitted reviews and PR discussion comments, showing blocker and warning counts from the latest recognizable report. It accepts explicit `<!-- review blockers=1 warnings=7 ... -->` metadata or Markdown Blockers/Warnings sections with top-level list items (or “None”). Counts are reported findings, not an inferred GitHub approval decision. GitHub approval takes precedence over “No findings” and stays visible alongside any reported warnings or blockers; the tooltip retains the report date and URL. Changes to the pushed PR head, title, or description after the latest report keep its counts visible with a note naming what changed: **Commits changed since review**, **PR title changed since review**, or **PR description changed since review** (combined when several changed). Short reviewed commit IDs are matched to GitHub’s full IDs. Commit identity detects branch changes; title events and description edit timestamps detect PR edits. Labels, draft-state changes, references from other branches or PRs, and ordinary discussion do not mark the report outdated. Local edits and unpushed commits are shown separately on the card. If freshness cannot be checked, findings remain visible with **Review freshness unavailable**; unavailable posts are labeled **Review unavailable**. When no open PR exists, DevJay checks the latest 20 merged PRs for the same repository and branch. Only a checkout at the merged PR’s exact tip can show **Merged · Branch left over after merge**. A different tip has no association with the old PR. When the local reflog retains the branch’s creation record, a creation date after the merge also rules out the old PR, even at the same commit. Recreating a branch invalidates its cached GitHub status. If creation history is unavailable or expired, DevJay requires the exact tip and never infers a relationship from the name or shared ancestry alone. Local edits remain visible, and this is not a claim that deleting the branch is safe. Default branches do not show this leftover status. Dismissed and pending reviews are excluded. Ordinary discussion does not replace a report, and findings are not summed across repeated reviews. Missing CLI/authentication or network failures show **GitHub unavailable**. This version does not track individual unread comments or provide a review inbox. GitHub Enterprise and fork PRs targeting another repository are not resolved yet. Commands have bounded duration, output, and concurrency; interactive authentication prompts are disabled.

## Persistence and desktop APIs

Sites and custom order are stored atomically in `~/Library/Application Support/DevJay/sites.json`. A malformed configuration is reported and never silently overwritten. Window positions, display identity, desktop UUID, and appearance preferences are stored in macOS preferences under the `io.teamconclude.devjay` bundle identifier. Development builds use `~/Library/Application Support/DevJay Development/sites.json` and the `io.teamconclude.devjay.development` preferences domain. Each folder has a stable identifier, so removing and re-adding it recovers its previous placement.

The control panel remembers its size. Windows within 10% of the usable screen width or height of the nearer right or bottom edge preserve their gap in points when the resolution changes. Restored windows are clamped 8 points inside the usable display area. Missing displays fall back to the nearest available screen. Desktop identification and restoration use runtime-loaded private SkyLight APIs. Failed restores preserve the saved desktop assignment until the Site is moved; removed desktops or unavailable APIs leave windows accessible. These undocumented APIs may change with macOS updates. The main window skips desktop restoration when shown on all desktops.

## Recovering blank windows

After display/system wake or returning to the login session, DevJay reloads its web views once the display has settled. WebContent process termination also triggers recovery if WebKit's own reload does not restore a rendered snapshot. Reloads preserve native window positions, visibility, and backend Git operations; they do not repeat or confirm an action. Transient UI state such as text selection and scroll position may reset.

Recovery waits for fresh frontend state and retries at most three times per incident, with a rate limit for repeated crashes. Regular snapshots are paused while the display or session sleeps. If windows remain blank, use **View → Reload windows** to retry without quitting. Recovery events are logged with the prefix `UI recovery:`. A persistent macOS GPU failure can still require restarting DevJay or macOS.
