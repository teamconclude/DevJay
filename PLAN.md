# Remaining work

Reviewed against the implementation on 24 September 2026. Keep this file: the items below are still missing features or unresolved validation/release work. They are candidates for future work, not instructions to implement them all. Current behavior belongs in the [user guide](docs/USER_GUIDE.md) and [architecture reference](docs/ARCHITECTURE.md).

## What has already shipped in the implementation

The old roadmap understated the current app. Diff/history viewers, editor opening, guarded branch switching and fast-forward updates, return after a merged PR with optional branch deletion, trial rebases, ordinary pushes, and rewritten-upstream replacement are implemented. Fetches coordinate by common Git directory, asynchronous remote results use identity/generation checks, and wake/WebKit recovery is present. Universal DMG packaging and separate development storage are also implemented.

Rewritten-upstream replacement uses exact upstream reflog evidence plus confirmation and recovery refs. This supersedes the old proposal to require a designated review checkout and a separately persisted synchronized-HEAD baseline. Recovery refs survive restart and are exposed in action results; a dedicated recovery browser is not implemented. These mechanisms still need validation under external changes and failures; implementation is not platform certification.

Changes/History window placement follow-up on 1 October: new viewers use the originating card's inward placement, then seek nearby free space around viewers on the active desktop or offset crowded windows to keep their title bars distinguishable. Reused viewers preserve their position. All 144 JavaScript tests, focused Go viewer/card-menu regressions, Go vet, 62 geometry checks and native window-placement checks passed. Coverage includes card-bound delivery, invalid geometry, free/crowded layouts, negative display coordinates, and excluding hidden, minimized, other-desktop and other-display viewers. The signed development app was rebuilt, verified and relaunched; a real Changes window opened from its card and was closed after the check. No Git action was performed. Live multi-monitor/Space transitions and crowded-desktop placement still need manual verification.

## Optional later enhancements

- Extend the initial waiting indicators to standalone desktop apps, custom agent-home locations, remote sessions, and Codex sessions outside the default local daemon. Keep confirmed waiting separate from attention requested and response ready. Current indicators combine explicit Claude registry/Codex daemon state with best-effort folder and host-process evidence, refreshing about every ten seconds; they do not prove a particular window/tab owns the session. Optional integrations could improve association and update latency. Revalidate the local interfaces across agent versions.
- Configurable global shortcuts and an optional menu-bar entry (current shortcuts are app-local).
- A compact freshness/status details view and a discoverable recovery-reference browser.
- Automatic app updates after a reliable signed release process exists.
- Visibility limited to desktops containing Sites, if platform support is reliable.

Out of scope: managing editors/agent sessions, creating Spaces, running development servers/tunnels/proxies, becoming a full Git client, automatic merging/pushing, cross-platform UI, and Mac App Store distribution. Preserve the Git safety boundaries documented in [AGENTS.md](AGENTS.md) and [the architecture reference](docs/ARCHITECTURE.md#git-safety-boundaries).
